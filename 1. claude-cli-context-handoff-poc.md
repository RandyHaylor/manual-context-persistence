# Claude CLI Context-Handoff POC

## Purpose

- Custom Python app launched from the project working directory
- Claude CLI as the first supported harness
- tmux as the first supported method for launching and controlling the interactive user interface
- One persistent base session
- Short user-facing branch sessions
- Base session kept compact through accumulated handoffs

## Core Turn Loop

1. Start from the current base session
2. Launch a user-facing branch
3. Let the user and agent complete one turn
4. Capture the user prompt verbatim
5. Capture the agent-selected context-to-keep
6. Submit both to the base session through a normal Claude chat message
7. Request acknowledgment only
8. Launch the next user-facing branch from the updated base session

## Base Session

- Initial session preamble
- Accumulated user prompt material selected for inclusion
- Accumulated context-to-keep handoffs
- Brief acknowledgment responses
- No full branch transcript
- No full project memory

## POC Adapters

- Claude CLI and tmux remain important parts of this POC
- Claude CLI integrated through a generic harness interface
- tmux integrated through a generic user-interface control interface
- Core turn loop must not depend directly on Claude CLI commands
- Core turn loop must not depend directly on tmux commands
- Another harness may replace Claude CLI later
- Another launch or user-interface control method may replace tmux later
- Adapter boundaries required both for future integration and basic code quality

## Startup

- Assume the user is logged in and authenticated to Claude CLI
- Verify `cwd/.claude/settings.local.json`
- Verify the Stop hook
- Verify the UserPromptSubmit hook
- Ask whether to create a new session or resume a session
- Create the base session with the custom preamble, or load it
- Open the shared tmux window
- Use an ID derived from the base session ID
- Launch a Claude CLI user session as a branch of the base session

## User Prompt Capture

- Log prompts verbatim to `.claude/user-prompt-log.json`
- Each entry carries the current session and user text string
- Capture up to 2,000 characters before each prompt
- Look back for previous mid-turn user prompt submissions
- Use the source-of-truth skill implementation as the reference for this capture behavior

## Context-to-Keep Capture

- Watch `cwd/.claude/context-to-keep.json` for changes
- Treat a change as new context from a completed turn
- The Stop hook looks for the custom JSON package in the active session response
- The package contains what the agent decides is needed going forward
- The handoff must preserve enough context to understand what was done in the last turn

## Turn Rotation

1. Read the new context-to-keep
2. Collect matching user prompt log entries for that session
3. Send `Ctrl+C` twice to the shared tmux window
4. Echo `updating base session...`
5. Use `claude -p` to submit the user prompts and context-to-keep to the base session
6. Include an instruction to acknowledge receipt only
7. Wait for the acknowledgment response
8. Launch a new Claude CLI session for the user as a branch of the updated base session
9. Keep using the same shared tmux window

## Context File Rotation

1. Add a timestamp to the processed `context-to-keep.json`
2. Move it to `.claude/context-to-keep-history/context-to-keep-<timestamp>.json`
3. Create a new empty `.claude/context-to-keep.json`
4. Continue watching for the next turn

## Session Flow

```text
Initial base session
└── User-facing branch
    ├── User request
    ├── Agent work, action, or response
    └── Capture agent context-to-keep
            ↓
       Submit to base session:
       - User prompt material
       - Agent context-to-keep
       - Acknowledge-only instruction
            ↓
       Base session acknowledges
            ↓
       New user-facing branch
```

## Python Structure

- No monolithic Python files
- Small modules with one narrow responsibility
- Clear separation between:
  - Orchestration layer
  - Harness interfaces and Claude CLI adapter
  - User-interface control interfaces and tmux adapter
  - Business logic
  - File watching and persistence helpers
  - Hook-related helpers
- Orchestration coordinates the turn loop
- Interfaces define required behavior without binding the core to one implementation
- Adapters contain Claude CLI or tmux-specific behavior
- Business logic contains context-handoff flow independent of the adapters
- Modules remain small enough to understand, test, and replace independently

## Core Files

```text
.claude/settings.local.json
.claude/user-prompt-log.json
.claude/context-to-keep.json
.claude/context-to-keep-history/context-to-keep-<timestamp>.json
```

## Design Principles

- Keep the mature system as a small, generic turn loop
- Keep Claude CLI and tmux central to this POC without embedding them in the core
- Put harness-specific and user-interface-specific behavior behind replaceable interfaces
- Keep orchestration, adapters, and business logic separate
- Prefer many small focused modules over monoliths
- Do not turn the core into a workflow engine
