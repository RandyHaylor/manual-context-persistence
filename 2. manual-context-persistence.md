our custom python app launches from project working dir
	assume logged in and auth'd to claude cli
		(code written with proper interfaces to allow integrating other harnesses later)
	verifies that the cwd's .claude/settings.local.json has the proper stop hook and user prompt submit hook to capture the context-to-keep from the active session's response and the user prompt submissions for inclusion	
	asks user if they want a new session or to resume a session
	creates the session (we'll inject our own preamble here for the session) or loads it
	opens the shared tmux window with id created from session-id of base session
	launches a claude cli user session as a branch of the base session for the user to interact with
	user prompts are logged verbatim to a .claude/user-prompt-log.json which carries current session and user text string for each entry
	actively watches the cwd/.claude/context-to-keep.json file for changes - indicating a turn was done and new context added
	once changes detected, code automatically injects new context-to-keep as well as grabbing any user prompt log entries for that session as well (user prompt logs capture 2000 chars before them and also look back to capture previous mid-turn user prompt submissions - see the source-of-truth skill's implementation for how to acheive this)
	when a context-to-keep update is detected and processed:
		shared tmux window is sent keystrokes to cancel the session (ctrl+c x2)
		echo is sent saying 'updating base session...'
		a claude -p call used to inject user prompts from log and the context-to-keep (and instruction to only acknowledge)
		launch a new claude cli session for user as branch of the base session after the ack response is recieved from the claude -p call		
		context-to-keep.json is given a timestamp and moved to .claude/context-to-keep-history/context-to-keep-<timestamp>.json
		a new empty context-to-keep.json created
